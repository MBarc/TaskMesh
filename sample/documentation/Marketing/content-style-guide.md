# Content Style Guide

**Document Owner:** Content Team
**Last Updated:** February 2024
**Version:** 2.1

## Purpose

This guide ensures consistency across all written content, from blog posts to product documentation.

## General Principles

### Write for Scannability
- Use headings and subheadings
- Keep paragraphs short (3-4 sentences)
- Use bullet points for lists
- Bold key terms sparingly

### Know Your Audience
- Primary: IT decision-makers
- Secondary: Technical practitioners
- Tertiary: Business stakeholders

## Grammar & Mechanics

### Capitalization

| Element | Style | Example |
|---------|-------|---------|
| Headlines | Title Case | "How to Improve Your Workflow" |
| Subheadings | Sentence case | "Getting started with integrations" |
| Product names | As branded | "TaskMesh Pro" |
| Features | Lowercase | "the dashboard feature" |
| Job titles | Capitalize before name | "CEO Jane Smith" / "Jane Smith, the CEO" |

### Punctuation

**Oxford Comma:** Yes, always use it.
- Correct: "We offer speed, reliability, and security."
- Incorrect: "We offer speed, reliability and security."

**Dashes:**
- Em dash (—) for breaks in thought—like this
- En dash (–) for ranges: "pages 10–15"
- Hyphen (-) for compound words: "best-in-class"

**Quotation Marks:**
- Use double quotes for direct quotes
- Use single quotes for quotes within quotes
- Periods and commas go inside quotes

### Numbers

| Type | Style | Example |
|------|-------|---------|
| 1-9 | Spell out | "five users" |
| 10+ | Numerals | "15 integrations" |
| Starting sentences | Spell out | "Twenty-three percent..." |
| Statistics | Numerals | "increased by 3%" |
| Money | Numerals | "$5.99" or "$5 million" |
| Dates | Month Day, Year | "January 15, 2024" |
| Time | Numerals with am/pm | "10:30 am ET" |

## Product & Technical Writing

### Product Names
- First mention: Full name ("TaskMesh Pro")
- Subsequent mentions: Short name okay ("TaskMesh" or "the product")
- Never: "TM" or other abbreviations in external content

### Technical Terms

| Term | Usage |
|------|-------|
| API | Always capitalized, no periods |
| SaaS | Always capitalized |
| login (noun) | "Enter your login" |
| log in (verb) | "Log in to continue" |
| set up (verb) | "Set up your account" |
| setup (noun/adj) | "Complete the setup process" |
| email | One word, lowercase |
| ecommerce | One word, lowercase |

### UI Elements
- Bold button names: Click **Save**
- Capitalize menu items as shown: Go to **Settings > Account**
- Use "select" for dropdowns, "click" for buttons, "enter" for text fields

## Content Types

### Blog Posts
- Length: 800-1,500 words
- Include meta description (150-160 characters)
- Add 2-4 internal links
- Include relevant images with alt text
- End with clear CTA

### Product Documentation
- Task-oriented (what users need to do)
- Step-by-step format
- Include screenshots for complex processes
- Keep sentences under 25 words

### Email
- Subject line: 6-10 words
- Preview text: Extends subject, doesn't repeat
- Body: 150-200 words for newsletters
- One clear CTA per email

### Social Media

| Platform | Character Limit | Tone |
|----------|-----------------|------|
| LinkedIn | 3,000 (first 140 visible) | Professional |
| Twitter/X | 280 | Concise, engaging |
| Instagram | 2,200 (first 125 visible) | Visual-focused |

## Inclusive Language

### Do
- Use gender-neutral language ("they" as singular)
- Be specific about demographics when relevant
- Use person-first language ("person with a disability")
- Consider global audiences

### Don't
- Use gendered terms ("guys," "manpower")
- Make assumptions about readers
- Use idioms that don't translate globally
- Use ableist language ("crazy," "blind to")

## SEO Guidelines

### Keywords
- Include primary keyword in H1 and first paragraph
- Use related keywords naturally throughout
- Don't stuff keywords or sacrifice readability

### Meta Information
- Title tag: 50-60 characters, primary keyword near beginning
- Meta description: 150-160 characters, include CTA

## Review Process

1. Writer completes draft
2. Peer review for content accuracy
3. Editor review for style compliance
4. Final approval from content lead
